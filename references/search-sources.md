# 快速搜索来源

仅在需要外部搜索时读取。本流程的目标是快速发现 Agent Skills，不是调查整个开源生态。

## 查询

从用户原话生成一个主要英文查询。只有同义词、专业术语或中英文变体可能带来不同结果时，再增加最多两个查询。

宽泛需求也直接搜索。例如“毕业论文相关 Skill”可用 `thesis academic writing` 作为主查询，并按结果情况补充 `literature review citation` 或 `docx thesis formatting`。先展示不同用途的结果，不要在搜索前要求用户完整拆解需求。

## 来源顺序

1. 当前已安装 Skill 的名称和 `description`；
2. 环境中已经存在的 Skills CLI / skills.sh；
3. 前两项结果不足时，补充 GitHub 中可定位到具体 `SKILL.md` 的仓库；
4. 中文需求且结果不足时，再选择一个当前可访问、能回到规范源码的中文目录。

独立来源可以并行查询。不要为了看起来全面而同时访问大量目录，也不要为了搜索自动安装或升级 CLI。

## Agent Skill 类型确认

进入推荐的候选必须满足：

- 能定位到具体 Skill 目录；
- 目录中存在可读取的 `SKILL.md`；
- frontmatter 至少能识别 `name` 和 `description`；
- 存在适用于当前 Skills CLI 的仓库与 Skill 标识。

MCP server、Plugin、App、Agent、包、模板集合和普通仓库即使被搜索源返回也应排除。多 Skill 仓库必须记录具体 Skill 路径，不能把整个仓库当成一个 Skill。

## 候选处理

搜索阶段只收集名称、描述、规范仓库网址、Skill 路径、安装标识和已安装状态。按“仓库网址 + Skill 路径”去重，不按名称误合并不同来源。

先按任务匹配排序。默认保留一个主推荐和最多四个有实际差异的备选；无关结果不展示。安装量、Stars、作者和更新时间不是默认筛选条件。

主推荐确定后停止扩大搜索，除非当前结果明显缺少用户要求的关键能力或用户明确要求更广泛比较。
